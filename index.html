Sobre este manual

Este manual organiza el material proporcionado sobre programación multihilo en Java. Conserva sus nueve bloques temáticos, sus conceptos, tablas, ejemplos y diez ejercicios resueltos. La redacción y la composición se han adaptado a un formato de estudio para alumnado de Formación Profesional de Desarrollo de Aplicaciones Multiplataforma (DAM).

Criterio editorial: el contenido técnico procede exclusivamente del documento original. No se han incorporado temas externos ni bibliografía. Los ejercicios incluyen una explicación didáctica de sus instrucciones, manteniendo el código de partida.

01 · FUNDAMENTOS

Conceptos básicos de programación multihilo

Comprende qué es un hilo, cómo se organiza dentro de un proceso y por qué resulta útil.

01
DOCUMENTO ORIGINAL · PÁGINA 3
  1. Conceptos básicos

1.1. Programa y flujos de ejecución

Un programa es un conjunto de instrucciones que realiza actividades o tareas.

Según cómo se ejecuten estas tareas, podemos distinguir dos tipos de flujos:

  • Flujo único: las tareas se ejecutan de forma secuencial, una después de otra.
  • Flujo múltiple: varias tareas pueden ejecutarse de forma concurrente y, dependiendo del hardware,

simultáneamente. La programación multihilo consiste en utilizar varios flujos de ejecución, denominados threads o hilos, dentro de un mismo proceso.

1.2. Flujos de ejecución

Un hilo de ejecución es:

  • Un flujo de control secuencial independiente dentro de un proceso.
  • La unidad básica de planificación y utilización de la CPU.
  • Una secuencia de instrucciones que se ejecuta dentro de un proceso.

Cada hilo tiene su propio estado de ejecución, pero puede compartir recursos con otros hilos pertenecientes al mismo proceso.

1.3. Hilos: conceptos

  • Los hilos dependen de un proceso.
  • Los procesos son independientes y tienen espacios de memoria separados.
  • Un proceso puede tener varios hilos compartiendo memoria.
  • Todo proceso en ejecución dispone de al menos un hilo de ejecución.
  • Los hilos de un mismo proceso pueden acceder a los mismos datos compartidos.
  • Cada hilo puede ejecutar una tarea diferente.

1.4. Hilos vs. procesos

Un proceso es un programa en ejecución que dispone de su propio espacio de memoria y recursos.

Un hilo es una unidad de ejecución que forma parte de un proceso.

CaracterísticaProcesoHilo

Independencia Independiente Depende de un proceso

Memoria Espacio propio Comparte memoria del proceso

Comunicación Requiere mecanismos de comunicación Puede utilizar memoria compartida

Creación Generalmente más costosa Generalmente más rápida

Recursos Mayor consumo Menor consumo

Cambio de contexto Generalmente más costoso Generalmente más rápido

Ejecución Puede contener varios hilos Ejecuta una secuencia de instrucciones

1.5. Elementos de los hilos

Elementos propios

Cada hilo tiene:

  • Identificador único: permite distinguir un hilo de los demás.
DOCUMENTO ORIGINAL · PÁGINA 4
  • Contador de programa: indica la siguiente instrucción que debe ejecutarse.
  • Conjunto de registros: almacena información temporal necesaria para la ejecución.
  • Pila: almacena las llamadas a métodos, parámetros y variables locales.

Elementos compartidos

Los hilos pertenecientes al mismo proceso comparten:

  • Código: instrucciones del programa.
  • Datos: objetos y variables almacenados en memoria compartida.
  • Recursos: ficheros, conexiones y otros recursos del proceso.

Aunque los hilos compartan memoria, cada uno mantiene su propia pila de ejecución.

1.6. Ventajas de los hilos frente a los procesos

Las principales ventajas son:

  1. Creación y finalización más rápida: crear o finalizar un hilo suele requerir menos operaciones.
  2. Menor consumo de recursos: los hilos aprovechan los recursos compartidos del proceso.
  3. Cambio de contexto más rápido: cambiar entre hilos del mismo proceso suele ser menos costoso.
  4. Mayor capacidad de respuesta: una tarea larga no tiene por qué bloquear todas las demás.
  5. Mejor aprovechamiento de procesadores multinúcleo: diferentes hilos pueden ejecutarse simultáneamente

en distintos núcleos.

1.7. Capacidad de respuesta

Los hilos permiten a los procesos continuar atendiendo peticiones del usuario, aunque alguna de las tareas que esté realizando el programa sea muy larga.

Por ejemplo, en un servidor, una petición puede tardar varios segundos en completarse sin impedir que se atiendan otras peticiones.

Ejemplo: servidor con hilos para cada petición Un hilo se encarga de recibir las peticiones de los usuarios y, por cada petición, se lanza un nuevo hilo para responderla.

De esta forma, se pueden tratar varias peticiones de manera concurrente.

Funcionamiento

  1. El servidor recibe una petición.
  2. Crea un hilo para atenderla.
  3. El hilo procesa la petición.
  4. Mientras tanto, el servidor continúa recibiendo nuevas peticiones.
  5. Cuando termina su tarea, el hilo finaliza.

Este modelo es sencillo, aunque en servidores reales suele ser preferible utilizar grupos de hilos (thread pools) para evitar crear un número excesivo de hilos.

1.8. Compartir y ahorrar recursos

Los hilos permiten compartir y ahorrar recursos porque:

  • Comparten la memoria del proceso.
  • Pueden comunicarse mediante datos compartidos.
  • No necesitan obligatoriamente mecanismos de comunicación entre procesos.
  • No requieren duplicar todos los recursos del proceso.
  • Cada hilo necesita únicamente sus propios recursos de ejecución, como su pila.
Importante

compartir memoria facilita la comunicación, pero también puede provocar problemas de concurrencia cuando varios hilos modifican los mismos datos.

DOCUMENTO ORIGINAL · PÁGINA 5

1.9. Uso recomendado

La programación multihilo es especialmente útil en:

  • Aplicaciones con tareas simultáneas.
  • Programas que utilizan múltiples dispositivos de entrada o comunicación.
  • Entornos multiprocesador.
  • Tareas con distintas prioridades.
  • Servidores que atienden varias peticiones.
  • Aplicaciones con interfaces gráficas que deben permanecer operativas.
  • Procesamiento paralelo de grandes cantidades de datos.
  • Aplicaciones que realizan operaciones de entrada y salida.
02 · SISTEMAS

Multitarea y multiprogramación

Distingue la gestión de varias tareas, la multiprogramación, la concurrencia y el paralelismo.

02
DOCUMENTO ORIGINAL · PÁGINA 6
  1. Multitarea vs. multiprogramación

2.1. Multitarea

La multitarea es la capacidad de un sistema operativo para gestionar varias tareas durante un mismo período de tiempo.

En un sistema con un solo núcleo, el procesador alterna rápidamente entre tareas, creando la impresión de que se ejecutan simultáneamente.

En un sistema multinúcleo, algunas tareas pueden ejecutarse realmente al mismo tiempo.

Ejemplo

Un ordenador puede:

  • Reproducir música.
  • Descargar un archivo.
  • Ejecutar un navegador.
  • Compilar un programa Java.

Todas estas tareas pueden progresar concurrentemente.

2.2. Multiprogramación

La multiprogramación consiste en mantener varios programas en memoria para aprovechar mejor la CPU.

Cuando un programa debe esperar una operación de entrada o salida, el sistema operativo puede ejecutar otro programa.

Objetivo principal: evitar que la CPU permanezca inactiva cuando existen programas preparados para ejecutarse.

2.3. Diferencias

CaracterísticaMultitareaMultiprogramación

Objetivo Gestionar varias tareas con buena Mejorar el aprovechamiento de la CPU capacidad de respuesta

Funcionamiento Alternancia o ejecución paralela de Mantener varios programas disponibles tareas para ejecutar

Enfoque Concurrencia y respuesta Utilización del procesador

Ejemplo Navegar mientras se reproduce música Ejecutar otro programa cuando uno espera una operación de E/S

2.4. Concurrencia vs. paralelismo

Concurrencia: varias tareas progresan durante un mismo intervalo de tiempo, aunque no necesariamente ejecutándose al mismo instante.

Paralelismo: varias tareas se ejecutan realmente al mismo tiempo, normalmente utilizando diferentes núcleos de CPU.

Por tanto:

  • Puede existir concurrencia sin paralelismo.
  • El paralelismo implica ejecución simultánea.
  • La programación multihilo permite concurrencia y puede aprovechar el paralelismo.

  1. Hilos en Java

3.1. Creación de hilos

En Java existen dos formas básicas de definir tareas para ejecutarlas mediante hilos:

  1. Heredar de la clase Thread.
  2. Implementar la interfaz Runnable.

En ambos casos se utiliza start() para iniciar un nuevo hilo, que ejecutará el método run().

Diferencia importante:

  • start() inicia un nuevo hilo.
  • run() ejecutado directamente funciona como una llamada normal a un método y no crea otro hilo.

3.2. Opción 1: extends Thread

Esta opción consiste en:

  1. Crear una subclase de Thread.
  2. Sobrescribir el método run().
  3. Crear objetos de esa clase.
  4. Llamar al método start().

Ejemplo completo

JAVA
public class HiloEjemplo1 extends Thread {
private int c; // contador del hilo
private int numero_hilo;
// Constructor
public HiloEjemplo1(int numero) {
this.numero_hilo = numero;
System.out.println("Creando hilo: " + numero_hilo);
}
@Override
public void run() {
c = 0;
while (c < 5) {
System.out.println(
"Hilo número: " + numero_hilo
+ " Contador(c) = " + c
);
c++;
}
}
public static void main(String[] args) {
for (int i = 1; i <= 3; i++) {
HiloEjemplo1 h = new HiloEjemplo1(i);
h.start();
}
System.out.println("3 hilos creados");
}
}

Explicación

  • extends Thread indica que la clase hereda de Thread.
  • numero_hilo identifica cada hilo.
  • El constructor recibe el número del hilo.
  • run() contiene las instrucciones que ejecutará el hilo.
DOCUMENTO ORIGINAL · PÁGINA 8
  • El bucle while muestra cinco valores del contador.
  • start() inicia cada hilo.
  • El método main() crea tres hilos.

Los mensajes pueden aparecer en diferente orden en cada ejecución porque los hilos se planifican de manera concurrente.

3.3. Opción 2: implements Runnable

La interfaz Runnable define el método run().

Sus principales ventajas son:

  • Permite heredar de otras clases.
  • Separa la tarea que debe ejecutarse del hilo que la ejecuta.
  • Facilita la reutilización del código.
  • Es compatible con APIs de concurrencia como ExecutorService.

Ejemplo completo

JAVA
public class HiloEjemplo2 implements Runnable {
private int numero_hilo;
public HiloEjemplo2(int numero) {
this.numero_hilo = numero;
System.out.println(
"Creando hilo (Runnable): " + numero_hilo
);
}
@Override
public void run() {
for (int i = 0; i < 5; i++) {
System.out.println(
"Hilo (Runnable) número: "
+ numero_hilo + " i = " + i
);
}
}
public static void main(String[] args) {
for (int i = 1; i <= 3; i++) {
Thread hilo = new Thread(new HiloEjemplo2(i));
hilo.start();
}
System.out.println("3 hilos (Runnable) creados");
}
}

Explicación

  • implements Runnable indica que la clase implementa la interfaz.
  • run() define la tarea.
  • new HiloEjemplo2(i) crea el objeto que contiene la tarea.
  • new Thread(...) crea el hilo encargado de ejecutarla.
  • start() inicia el hilo.
  • Se crean tres hilos, cada uno con cinco iteraciones.

3.5. Estados de un hilo en Java

Los hilos pueden encontrarse en diferentes estados:

EstadoDescripción

NEW El hilo ha sido creado, pero todavía no se ha iniciado

RUNNABLE Está preparado para ejecutarse o ejecutándose

BLOCKED Espera adquirir un bloqueo de monitor

WAITING Espera indefinidamente a que ocurra un evento

TIMED_WAITING Espera durante un tiempo determinado

Ejemplo

JAVA
public class EstadosHilo {
public static void main(String[] args)

System.out.println("Hilo ejecutándose");
});
System.out.println(hilo.getState());
hilo.start();
hilo.join();

}
}

  1. Métodos útiles de la clase Thread

4.1. Métodos estáticos

Los métodos estáticos pertenecen a la clase Thread y pueden utilizarse sin crear un objeto de esa clase.

4.1.1. currentThread()

Devuelve el hilo que se está ejecutando en ese momento.

Ejemplo

JAVA
System.out.println(
Thread.currentThread().getName()
);
// Muestra: main

Explicación

El método obtiene el hilo actual, que en este caso es el hilo principal del programa, y muestra su nombre.

4.1.2. sleep(long ms)

Pausa la ejecución del hilo actual durante el tiempo especificado en milisegundos.

Ejemplo

JAVA
Thread.sleep(1000); // Pausa 1 segundo
System.out.println("Un segundo después");

Explicación

El hilo principal se suspende durante aproximadamente un segundo antes de continuar.

El método puede lanzar InterruptedException, por lo que debe gestionarse mediante try-catch o declararse con throws.

Ejemplo con gestión de excepción:

JAVA
try {
Thread.sleep(1000);
} catch (InterruptedException e) {
Thread.currentThread().interrupt();
}

4.1.3. yield()

Sugiere al planificador que el hilo actual está dispuesto a ceder temporalmente el procesador.

Ejemplo

JAVA
for (int i = 0; i < 3; i++) {
System.out.println(
"Hilo actual: "
+ Thread.currentThread().getName()
);
Thread.yield();
}

Explicación

El hilo cede voluntariamente su oportunidad de ejecución, aunque no garantiza que otro hilo vaya a ejecutarse.

DOCUMENTO ORIGINAL · PÁGINA 11

4.2. Métodos de instancia

4.2.1. start()

Inicia el hilo y permite que se ejecute su método run().

Ejemplo

JAVA
Thread t = new Thread(
() -> System.out.println("Hilo iniciado")
);
t.start();

Explicación

Se crea un hilo con una tarea que imprime un mensaje y se inicia mediante start().

Si se llamara directamente a run(), la tarea se ejecutaría en el hilo actual.

4.2.2. run()

Contiene el código que debe ejecutar el hilo.

Ejemplo

JAVA
class MiHilo extends Thread {
@Override
public void run() {
System.out.println("Ejecutando en run()");
}
}
new MiHilo().start();

Explicación

Al sobrescribir run(), se define la tarea del hilo.

Cuando se llama a start(), Java inicia el hilo y ejecuta su método run().

4.2.3. stop() ⚠️ Obsoleto

Detiene un hilo de manera abrupta.

Ejemplo histórico:

JAVA
Thread t = new Thread(() -> {
while (true) {
System.out.println("Ejecutando...");
}
});
t.start();
// t.stop(); // Obsoleto y no recomendado

Explicación

Este método es inseguro porque puede interrumpir operaciones y dejar objetos en estados inconsistentes.

En versiones modernas de Java no debe utilizarse.

Alternativa recomendada: utilizar interrupt() o mecanismos de cancelación cooperativa.

4.2.4. suspend() / resume() ⚠️ Obsoletos

Estos métodos permitían suspender y reanudar un hilo.

Ejemplo histórico:

DOCUMENTO ORIGINAL · PÁGINA 12
JAVA
// t.suspend(); // Pausaba el hilo
// t.resume(); // Reanudaba el hilo

Explicación

Son métodos inseguros porque pueden provocar bloqueos permanentes o dejar recursos bloqueados.

Se recomienda utilizar mecanismos de sincronización como wait(), notify(), Lock y Condition, según el caso.

4.2.5. join()

Espera a que un hilo termine antes de continuar con la ejecución del hilo que llama a este método.

Ejemplo

JAVA
Thread t = new Thread(
() -> System.out.println("Tarea en hilo")
);
t.start();
t.join();
System.out.println("El hilo ha terminado");

Explicación

El hilo principal espera hasta que t finaliza.

De esta forma, se garantiza que el mensaje final se muestre después de terminar la tarea.

4.2.6. setPriority() / getPriority()

Permiten establecer o consultar la prioridad de un hilo.

En los hilos tradicionales de Java, las prioridades van del 1 al 10.

  • Thread.MIN_PRIORITY: 1.
  • Thread.NORM_PRIORITY: 5.
  • Thread.MAX_PRIORITY: 10.

Ejemplo

JAVA
Thread t = new Thread(() -> {});
t.setPriority(Thread.MAX_PRIORITY);
System.out.println(t.getPriority()); // 10

Explicación

Se asigna la prioridad máxima al hilo.

Sin embargo, la influencia real de esta prioridad depende del sistema operativo y del planificador.

No garantiza que el hilo se ejecute antes que otros.

4.2.7. setName() / getName()

Permiten establecer o consultar el nombre de un hilo.

Ejemplo

JAVA
Thread t = new Thread(() -> {});
t.setName("Hilo Especial");
System.out.println(t.getName());
DOCUMENTO ORIGINAL · PÁGINA 13

Explicación

El nombre permite identificar los hilos durante la ejecución, depuración y análisis de errores.

4.2.8. interrupt()

Solicita la interrupción de un hilo.

Ejemplo

JAVA
Thread t = new Thread(() -> {
while (!Thread.currentThread().isInterrupted()) {
System.out.println("Trabajando...");
}
});
t.start();
t.interrupt();

Explicación

La interrupción es cooperativa: el hilo debe comprobar su estado o responder a InterruptedException.

No implica que termine inmediatamente.

4.2.9. isAlive()

Comprueba si un hilo ha comenzado su ejecución y todavía no ha terminado.

Ejemplo

JAVA
Thread t = new Thread(() -> {
System.out.println("Ejecutando");
});
t.start();
System.out.println(t.isAlive());

Explicación

Devuelve true si el hilo sigue activo y false si todavía no ha comenzado o ya ha terminado.

4.3. Constructores de Thread

4.3.1. Thread()

Crea un hilo sin tarea asociada.

Ejemplo

JAVA
Thread t = new Thread();
t.start();

Explicación

Se crea un hilo cuyo método run() no realiza ninguna tarea específica.

4.3.2. Thread(String name)

Crea un hilo con un nombre determinado.

Ejemplo

DOCUMENTO ORIGINAL · PÁGINA 14
JAVA
Thread t = new Thread("MiHilo");
System.out.println(t.getName()); // MiHilo

Explicación

El hilo tiene un nombre personalizado, pero no ejecutará ninguna tarea útil si no se define una.

4.3.3. Thread(Runnable target)

Crea un hilo que ejecutará la tarea definida por un objeto Runnable.

Ejemplo

JAVA
Runnable tarea = () ->
System.out.println("Hola desde Runnable");
Thread t = new Thread(tarea);
t.start();

Explicación

El hilo ejecuta el método run() de la tarea proporcionada.

4.3.4. Thread(Runnable target, String name)

Crea un hilo con una tarea y un nombre personalizados.

Ejemplo

JAVA
Runnable tarea = () ->
System.out.println("Ejecutando...");
Thread t = new Thread(
tarea,
"Hilo con nombre"
);
t.start();
System.out.println(t.getName());

Explicación

Este constructor permite establecer tanto el comportamiento del hilo como su nombre.

Sincronización de hilos en Java

Protege los recursos compartidos y coordina hilos mediante monitores.

DOCUMENTO ORIGINAL · PÁGINA 15
  1. Sincronización de hilos en Java

5.1. ¿Qué es la sincronización?

La sincronización permite controlar el acceso de varios hilos a recursos compartidos.

Su objetivo es evitar errores cuando diferentes hilos intentan leer o modificar los mismos datos simultáneamente.

5.2. Condiciones de carrera

Una condición de carrera (race condition) ocurre cuando el resultado de una operación depende del orden en que se ejecutan los hilos.

Ejemplo

JAVA
public class Contador {
private int contador = 0;
public void incrementar() {
contador++;
}
public int getContador() {
return contador;
}
}

Si varios hilos ejecutan incrementar() al mismo tiempo, pueden producirse pérdidas de incrementos.

Esto ocurre porque contador++ no es una operación atómica.

5.3. synchronized

La palabra clave synchronized permite que un único hilo a la vez ejecute una sección de código protegida por el mismo monitor.

Ejemplo

JAVA
public class Contador {
private int contador = 0;
public synchronized void incrementar() {
contador++;
}
public synchronized int getContador() {
return contador;
}
}

Explicación

  • Solo un hilo puede ejecutar a la vez los métodos sincronizados del mismo objeto.
  • Se evitan modificaciones simultáneas incompatibles.
  • Se protege la consistencia del contador.

5.4. Bloques synchronized

También es posible sincronizar únicamente una parte del código.

Ejemplo

DOCUMENTO ORIGINAL · PÁGINA 16
JAVA
public class Ejemplo {
private final Object bloqueo = new Object();
private int contador = 0;
public void incrementar() {
synchronized (bloqueo) {
contador++;
}
}
}

Explicación

Solo el bloque protegido necesita adquirir el monitor de bloqueo.

Esto permite limitar la región crítica.

5.5. wait()

El método wait() permite que un hilo espere hasta recibir una notificación.

Debe invocarse mientras se posee el monitor del objeto.

5.6. notify()

Despierta a uno de los hilos que estén esperando sobre el monitor de un objeto.

}

6.1. Lock y ReentrantLock

La interfaz Lock permite gestionar bloqueos explícitos.

ReentrantLock es una implementación que ofrece mayor control que un bloque synchronized en determinados escenarios.

Ejemplo

JAVA

import java.util.concurrent.locks.ReentrantLock;
public class EjemploLock {
private final Lock lock = new ReentrantLock();
private int contador = 0;
public void incrementar() {
lock.lock();
try {
contador++;
} finally {
lock.unlock();
}
}
}

Explicación

  • El código protegido modifica el contador.
  • unlock() libera el bloqueo.
  • finally garantiza que se intente liberar el bloqueo incluso si ocurre una excepción.

6.6. Deadlock o interbloqueo

Un deadlock ocurre cuando dos o más hilos quedan bloqueados esperando recursos que otros hilos mantienen ocupados.

Ejemplo conceptual:

  • El hilo A adquiere el recurso 1 y espera el recurso 2.
  • El hilo B adquiere el recurso 2 y espera el recurso 1.
  • Ninguno puede continuar.

Formas de prevenirlo:

  • Adquirir los bloqueos siempre en el mismo orden.
  • Evitar bloqueos innecesarios.
  • Reducir el tiempo de las secciones críticas.
  • Utilizar tryLock() cuando resulte apropiado.
  • Diseñar cuidadosamente el acceso a recursos compartidos.

  1. Conclusión

La programación multihilo permite desarrollar aplicaciones capaces de gestionar varias tareas concurrentemente, mejorar la capacidad de respuesta y aprovechar los procesadores multinúcleo.

En Java, los hilos pueden crearse mediante la clase Thread o la interfaz Runnable.

Los métodos start(), run(), sleep() y join() permiten controlar aspectos básicos de su ejecución.

Cuando varios hilos comparten datos, es necesario utilizar mecanismos de sincronización para evitar condiciones de carrera y problemas de consistencia.

Java proporciona herramientas como synchronized, Lock, Semaphore, AtomicInteger y ExecutorService para desarrollar aplicaciones concurrentes más seguras y eficientes.

Cierre

La programación multihilo permite que una aplicación gestione varias tareas concurrentemente y, cuando el hardware lo permite, aproveche la ejecución paralela. En Java, la creación de hilos, la coordinación entre tareas y la protección de los datos compartidos son elementos esenciales para construir programas correctos y capaces de responder a distintas necesidades de ejecución.

Este manual concluye con el resumen de conceptos y herramientas recogidos en el material original. Su propósito es servir como apoyo de estudio y consulta para el aprendizaje de programación multihilo en Java.
